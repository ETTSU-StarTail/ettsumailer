== 目的

ettsumailer は、RFC 準拠を重視したシンプルなデスクトップメーラである。
「メールを素早く読んで、必要な返信や対応を確実に行う」ことを主目的とし、
UI の派手さよりも可読性・安全性・軽快さを優先する。

== 目指す体験

* 起動後すぐに受信一覧を確認できる
* 重要なメールを迷わず開ける
* 表示崩れを最小化しつつ、危険な実行を抑制できる
* 設定・認証情報の扱いが分かりやすく安全である

== 設計原則

=== Less, but better
* 「Less, but better（より少なく、しかしより良く）」をデザイン哲学として採用する
* 画面要素・操作・設定項目は必要最小限に絞り、判断負荷を下げる
* 機能追加時は「本当に読むべきメールへ早く到達できるか」を優先基準にする

=== プロトコル準拠
* SMTP / IMAP などの標準仕様に沿って実装する
* メールフォーマット（RFC 5322 系）との整合を優先する

=== 安全側に倒す
* HTML メール表示は「読めること」と「安全性」のバランスを取る
* リモートスクリプト実行や追跡用途の処理は原則抑制する
* 外部リンクはアプリ内遷移ではなく既定ブラウザで開く

=== 軽量・単純
* フロントエンドはフレームワーク依存を避ける
* 機能は段階的に追加し、複雑性を必要以上に増やさない

=== 回復可能性
* 設定変更や接続失敗時の復旧手順を明確にする
* エラー時はユーザーが次に取るべき行動が分かるメッセージを優先する

== ターゲットユーザー

* 技術スタックを理解しながらメーラを運用したい個人開発者
* 重厚なグループウェアではなく、軽量なローカルクライアントを好むユーザー
* RFC ベースの実装を検証・学習したい利用者

== 提供価値

* *信頼性*: 標準プロトコル準拠による再現性の高い通信
* *安全性*: HTML メールの取り扱いを保守的に設計
* *可読性*: 余計な装飾を抑えた UI
* *拡張余地*: 将来的なフィルタ・分類・送受信強化へつなげやすい構成

== 機能差別化の方向性（構想）

「メールを素早く読んで、必要な返信や対応を確実に行う」を実現するため、
最初に読むべきメールを選定して優先表示する機能を構想する。

* 頻繁に送受信（コミュニケーション）しているドメインを優先度判定に利用する
* ルールベース（仕分け規則）で「目を通すべきメール」を抽出する
* まず優先メールだけをキャッチアップできる導線を提供する

NOTE: この優先キャッチアップ機能の名称は暫定であり、現在の `Compose` との関係（同一機能か別機能か）は今後整理する。

== 段階的実装ロードマップ

「読むべきメールへ最短到達」を実現するため、以下の機能を段階的に実装するが、盤や企画変更の可能性を承知おき。

=== MVP（Phase 1）

* **スター / フラグ**: 重要メールを即座に漏れなく抽出、表示切替
* **検索機能**: ワード・送信者で素早く検索

=== Phase 2

* **Must-Read 優先キャッチアップ**: ドメイン & ルールベースでVIP送信者を採択
* **VIP送信者通知**: 重要メール到着時に通知

=== Phase 3 (Future)

* **メール → TODO化**: 返信漏れを防止、優先キャッチアップモードで警告

== 非目標（現段階）

* 多人数コラボレーション機能（共有受信箱・承認フロー等）
* エンタープライズ向け管理機能（監査証跡、集中ポリシー配布等）
* 高度なマーケティングメール表現の完全再現（スクリプト依存 UI を含む）

== 成功指標（初期）

* アプリ起動から受信一覧表示までの体感時間が短い
* 主要な送受信ユースケースをエラーなく完了できる
* HTML メールで重大な安全問題（任意スクリプト実行）が発生しない
* 設定保存と資格情報管理が一貫して動作する
